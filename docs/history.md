# 대화 기반 작업 히스토리

정리일: 2026-11-18. 대상: Toss Front 1.5 PLF02WH.

## 이 문서의 범위와 신뢰도

이 문서는 이번 프로젝트로 이어진 대화의 사용자 결정, 이전 작업 보고, 조사 결과를 재구성한 인계 기록입니다. **대화 전체의 원문 전문이나 완전한 터미널 로그가 아닙니다.** 순서는 대화상 흐름이며 개별 작업의 정확한 시각이 확인되지 않은 경우 임의로 기입하지 않았습니다. 생성 시 기기나 Windows 백업을 재측정하지 않았습니다.

- **사용자 확인:** 실제 화면과 초기 설정 완료 등 사용자가 직접 알린 사항.
- **이전 작업 보고:** 도구 실행과 검증 결과를 이전 대화에서 보고한 내용. 해당 파일과 로그를 다시 확인해야 현재 증거가 됩니다.
- **정적 조사:** 소스·이미지·문서 분석이며 실기 동작 증거가 아닙니다.
- **미검증:** 아직 시험하거나 입증하지 않은 사항.

## 1. 시작과 설치 작업

사용자는 C 드라이브에 `toss` 폴더를 만들고 [PLF02WH 가이드](https://github.com/FLOVER124/toss-front-plf02wh-lineageos-guide)를 따라 작업하다 검토와 순차 진행을 요청했습니다. 이후 HOME-PC로 파일을 옮겨 작업했습니다.

사용한 기반은 [18.1 + Pico GApps 빌더](https://github.com/kyseong00/toss-front-lineageos-builder)입니다. 이는 소스 전체를 컴파일하는 PLF02WH 전용 포팅 프로젝트가 아니라, 기존 공용 시스템 이미지(GSI)와 기기에서 확보한 제조사 이미지를 가공·재패키징하는 방식입니다.

### 첫 부팅 및 초기 설정 문제

1. 설치 후 사용자는 LineageOS 로고가 보인다고 했지만 같은 화면에 계속 머물렀습니다.
2. 사용자 제공 [커뮤니티 글](https://gall.dcinside.com/mgallery/board/view/?id=sff&no=1728606)을 참고했고, 기존 사용자 데이터가 영향을 줄 가능성을 검토했습니다. 해당 글만으로 모든 부팅 루프의 원인을 확정할 수는 없습니다.
3. 사용자 승인하에 초기화 관련 조치를 진행했고 사용자는 정상 LineageOS 초기 설정 화면 진입을 확인했습니다.
4. 이후 시간 설정 다음으로 진행하지 못하는 문제가 발생했습니다. 사용자는 userdata를 지우고 처음부터 다시 진행하는 데 동의했습니다.
5. 이전 조사에서 **첫 가공 이미지의 ext4 공유 블록(shared blocks)을 다루는 삭제 과정이 남겨야 할 파일까지 훼손한 문제**를 확인했습니다. 단순히 사용자 데이터만의 문제라고 정리하면 안 됩니다.
6. 가공 로직과 블록 bitmap 관련 문제를 수정한 뒤 보존 대상 파일 6,706개의 내용·메타데이터·확장 속성(xattrs)을 비교했고, 최종 이미지 검증 후 super만 다시 기록했다는 작업 보고가 있습니다. 별도 승인된 userdata 초기화도 있었습니다.
7. 사용자는 최종적으로 초기 설정을 모두 완료했다고 확인했습니다.

최종 18.1 super SHA-256 이전 기록:
`BFC53AC3D388A93126F7604CAEEC26BD989D3D5CC6A94F29D275F8816F08844A`

이 해시는 전달된 기록입니다. 후속 작업자는 실제 파일과 대조하십시오. 순정 빌더를 그대로 다시 실행하면 같은 수정이 자동 반영된다고 가정하지 마십시오. 원본 소스와 수정본, 입력 이미지 및 결과 manifest를 확보해 차이를 확인하는 것이 선행 작업입니다.

- Google Play 스토어, Play 서비스, Google Services Framework 설치·활성 상태라는 이전 보고가 있습니다.

## 3. 백업과 정리 이력

이전 작업에서는 순정 주요 파티션과 userdata를 백업했습니다. 초기 Mac 작업 노트의 “userdata 미완성”은 이후 완료 작업보다 오래된 상태입니다.

### 현재 18.1 전체 사용자 영역 백업

- HOME-PC 위치: `C:\toss\lineage18-current-backup-20261118`
- eMMC 사용자 영역을 두 번 읽은 크기: 각각 **15,636,365,312 bytes**
- 두 파일의 동일 SHA-256 이전 기록:
  `D9F9392BCCE53ED1473DB61EF88033D3AEE471E5328ABF367E2D259E13F850F4`
- `verification.json`에 사용자 영역과 GPT/super 관련 검증 기록이 있다는 이전 보고가 있습니다.
- **별도 eMMC boot 영역과 RPMB는 범위 밖입니다.**
- **실제 복원 시험은 하지 않았습니다.** 해시 일치와 백업 존재는 복구 성공 보장이 아닙니다.

순정 백업 관련 이전 위치는 `C:\toss\backup-verified-20261117` 및 Windows 사용자 Tools 아래의 `toss-front`입니다. 정확한 파일 목록은 해당 PC에서 재확인해야 합니다.

사용자가 승인한 실패/임시 파일 6개 경로 약 39 GB 정리 이력이 있으나, 이 문서는 구체적 삭제 경로 원문을 보유하지 않으므로 추가 정리 근거로 사용하면 안 됩니다. 새 프로젝트 생성·이동 작업에서는 어떤 백업도 이동하거나 삭제하지 않았습니다.

### 23.2 실험 준비와 중단

사용자는 한때 23.2를 목표로 파티션 조정과 실기 시험도 검토했습니다. PC에서 4 GiB 실험용 super/GPT 구성 준비가 있었지만 **기기 GPT/파티션 변경은 실행하지 않았습니다.** 23.2 실부팅도 하지 않았습니다.

Windows RKDevTool의 GPT 쓰기 동작과 실제 보드의 물리 복구 진입이 충분히 검증되지 않았습니다. Rockchip `prm` 명령을 GPT 쓰기로 오인해 사용하면 안 됩니다. 이 문서는 하드웨어 접점 쇼트나 패드 조작 안내를 제공하지 않습니다. 사용자는 관련 하드웨어 지식이 없다고 밝혔습니다.

DSU를 통한 시험 가능성도 검토했지만 기존 가공 이미지에서 설치 서비스가 제거된 정황을 확인한 정도이며, 복원·DSU 부팅을 수행하지 않았습니다.

이후 사용자는 “23.2로 올리기 위해 너무 힘쓸 필요 없어 보인다”며 대안 OS부터 살펴보자고 방향을 바꾸었습니다. 23.2 강행이나 재파티션 계획을 자동 재개하면 안 됩니다.

## 5. 대안 OS 검토

정적 조사에서 AOSP 12.1 v416은 raw 1,815,252,992 B로 기존 system 한도 안에 들어가지만 2022-07 보안 패치와 GApps 미포함 문제가 있었습니다. AOSP 13 ponces 20230919는 raw 1,932,644,352 B, 파일시스템 영역 1,902,067,712 B로 재패키징 가능성을 살펴볼 여지가 있었지만 AVB/footer 등 분석과 실기 검증은 미완료였고 2023-09 보안 패치였습니다. 다른 최신 후보는 용량 또는 호환성 문제를 해결하지 못했습니다.

사용자는 당장 사용할 OS로 18.1을 유지하기로 했습니다. 이는 기술적 최대 버전을 18.1로 확정한 것이 아니라 당시 검증된 사용 상태를 유지하겠다는 결정입니다.

## 6. 시스템 방화벽과 USB 진단

사용자는 인바운드·아웃바운드 제어 및 시스템 방화벽에 관심을 보였습니다. AFWall+/iptables 등 방향을 논의했지만 root, SELinux, iptables/ip6tables 동작은 아직 확인하지 못했습니다. 앱의 `su` 권한과 ADB root는 별도입니다.

HOME-PC 읽기 전용 확인 결과:
- Windows에서 `TOSS_Front`, `VID_2207&PID_0006`, WinUSB 장치를 인식했습니다.
- USB 클래스 `FF/42/01`이 ADB 인터페이스임을 확인했습니다.
- 사용자는 홈 화면 및 “USB 디버깅으로 연결됨” 표시를 확인했습니다.
- 기존 RKDevTool 번들 adb는 **1.0.40 / 4797878**이며 `adb devices`는 비어 있었습니다. unauthorized 상태조차 표시되지 않았습니다.
- 예전 RKDevTool 로그에 `AdbCreateInterfaceByName failed, err=5`가 있었지만 현재 검사에서 오류 5를 재현하지는 못했습니다.
- RKDevTool/rkDumper/scrcpy 실행 프로세스는 발견하지 못했지만, 다른 프로세스의 USB 점유 가능성 전체를 배제한 것은 아닙니다.
- 임시 추적 ADB 서버는 종료했습니다. 기기·드라이버·방화벽 설정 변경은 하지 않았습니다.

최신 공식 ADB 비교 실행을 제안했으나 사용자가 출근해야 하므로 멈추고 **회사 Mac Studio에서 다시 진행**하기로 했습니다. 최신 도구 다운로드/설치를 승인받았다고 가정하지 마십시오.

## 7. 소스 빌드로 목표 변경

사용자는 단순히 최신 이미지를 설치하는 대신, 원하는 기능과 보안이 들어간 LineageOS를 소스부터 직접 빌드하고 싶다고 했습니다.

논의한 세 경로:
1. 기존 18.1 이미지 가공
2. LineageOS/GSI 소스부터 빌드
3. PLF02WH 전용 device tree와 커널까지 포팅

사용자의 궁극적 목표는 **2번**입니다. 조사에서 PLF02WH 전용 공개 device tree와 현재 커널에 정확히 대응하는 공개 소스는 찾지 못했지만, 존재하지 않는다고 확정한 것은 아닙니다. 초기에는 기존 kernel/vendor/odm을 유지하는 소스 기반 GSI 접근을 검토할 수 있으며, 실현 가능성은 미확정입니다.

사용자는 방화벽부터 정하자는 제안을 정정하여 **기본 범용 기능을 먼저 고른 뒤 커스텀 기능을 추가**하겠다고 했습니다. 또한 18.1은 너무 오래되므로 **LineageOS 24.0 최신 기능을 기준으로 검토**하기로 했습니다. 24.0이라는 기능 기준과 실제 빌드·설치 가능성은 구분해야 합니다.
