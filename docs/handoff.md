# 다음 작업 인계

기준일은 2026-11-23이다. 초기 검토를 넘어 LineageOS 21 빌드·설치·보안 수정·기능 시험과 실제 장치 승인 통신까지 진행한 작업 공간이다. 먼저 [현재 기기 상태](device-status.md)와 [전체 안내](../README.md)를 읽고, 날짜가 붙은 과거 기록을 현재 상태와 구분한다.

## 이어받을 상태

- LineageOS 21, ADB 인증, FBE, memtrack·Keymaster 교정과 KeliBoard 통합 결과가 기록돼 있다. 최신 이미지 해시와 남은 제약은 [기기 상태](device-status.md), [보안 검증](security.md), [기본 앱 통합](ime-system.md)을 따른다.
- 과거 PIN·CE 잠금 시험 성공과 현재 화면 잠금 상태는 다르다. 최신 기록에서는 사용자가 PIN을 제거해 화면 잠금이 “없음”이다.
- Mac Studio와 PLF02WH의 실제 LAN 승인·거부 왕복, 만료·취소·재사용 차단은 확인했다. 상세 범위는 [공통 승인 통신](../remote-unlock/README.md)에 있다.
- Mac 인증 호스트의 Allow/Deny 반환도 확인했지만, 사용자는 Mac 암호를 입력한 뒤 장치 버튼을 눌렀다. **암호 없는 독립 화면 해제·재잠금 보장·키체인 연동은 미검증**이다. [Mac 실기 기록](../remote-unlock/macos/approval/INSTALLATION.md)을 따른다.
- 마지막 Mac 시험은 원래 인증 규칙 복원과 플러그인·장치 시험 앱·서버·전용 키 제거를 마쳤다. 과거 설치 명령을 자동 재실행하지 않는다.

## 다음 작업을 정할 때

1. 빌드 재현을 이어가려면 [빌드 기록](build-gsi.md)의 소스 고정 한계와 외부 입력부터 확인한다. `manifests/`에 완전한 revision 고정 매니페스트가 있다고 가정하지 않는다.
2. 기기 기능을 이어가려면 [기본 기능](basic-features.md)과 [카메라 시험](camera-probe.md)의 완료·미검증 범위를 구분한다.
3. Mac 연동을 이어가려면 **암호 입력 전에 인증 요청을 시작할 수 있는 지원 경로**부터 읽기 전용으로 검토한다. 기존 통신의 성공을 화면 해제 성공으로 해석하지 않는다.
4. 외부 배포·기기 변경·macOS 인증 정책 변경은 새로운 영향·복구 범위를 제시한 뒤 진행한다.

## 변경 전 안전 점검

- 대상 기기는 PLF02WH인가?
- 원본/현재 백업은 별도 위치에 보존되는가?
- 명령이 PC 파일 생성인지 장치 쓰기인지 명확한가?
- 로컬 변경과 공개 업로드를 혼동하지 않았는가?
- 이미지/키/사용자 데이터가 Git에 포함되지 않는가?

공개 문서의 `PLF02WH_SERIAL`, `PLF02WH_MTP_SERIAL`, `MAC_STUDIO_HOST`는 익명화한 식별자다. 실제 작업에서는 현재 연결된 대상의 식별자를 확인해야 한다. 문서의 로컬 경로와 내부 주소도 해당 시험 환경의 기록이며 새 환경의 기본값이 아니다.
