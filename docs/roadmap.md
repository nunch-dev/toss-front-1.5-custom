# 단계별 계획

아래 체크리스트는 2026-11-18의 초기 계획 기록이다. 이후 완료된 빌드·설치·보안·기능 시험을 모두 반영한 현재 작업 목록이 아니다. 최신 상태와 다음 작업은 [기기 상태](device-status.md)와 [인계 문서](handoff.md)를 따른다.

## 2026-11-18 적용 현황

LineageOS 21 pre-QPR2 GApps 빌드·축소·VINTF 보완을 거쳐, 사용자 승인 후 super 512 MiB 확장과 userdata 초기화를 적용했다. 기록 전체 대조와 Android 14 첫 부팅, 초기 설정 화면, Wi-Fi 검색, Bluetooth ON을 확인했다. 아래의 초기 계획에서 보안 강화·전체 주변기기·복원 시험까지 완료된 것은 아니다.

현재 상태와 남은 검증은 [기기 상태](device-status.md), 정확한 기록 범위와 증거는 [super 확장 적용 기록](super-expansion.md)을 따른다.

## 0. 프로젝트 기준 확정
- [x] 별도 로컬 폴더와 요구사항 작성
- [x] 유지 희망 및 제외 후보 구분
- [ ] 미선택 앱의 기능 의존성 확인
- [ ] 기존 커널과 제조사 HAL을 유지하고 system GSI를 소스에서 빌드한다. 첫 빌드 후보는 21과 22 light를 우선 비교한다. 선택한 기능과 GApps를 포함한 ext4 크기, 커널·vendor 호환성을 비교한 뒤 사용자가 버전을 결정한다. 23.2는 추가 검토 후보이며 24.0은 기능 검토 기준이다. [커스텀 롬 제작 조사 2–4절](custom-rom-research.md)

## 1. 읽기 전용 조사
- [x] Mac Studio USB/ADB 경로 점검 및 셸 연결 재현 ([실측 결과](device-status.md#mac-studio-실측-2026-11-18))
- [ ] 기존 image/manifest/빌더 수정 이력의 위치와 해시 확인
- [ ] 현재 커널, vendor, VINTF, SELinux, 암호화 및 파티션 증거 수집
- [x] 커널의 EROFS·BPF 지원 여부 확인: EROFS 없음, 4.19 수준 BPF 있음, FBE 커널 기능 있음 ([근거](device-status.md))
- [ ] macOS용 rkdeveloptool/TF-Flasher로 Loader 인식만 확인(읽기·백업 전용, 쓰기 금지) (기본 속성과 VINTF target-level 확인, HAL 조각·파티션 용량 대조는 남음)
- [ ] 최신 소스 브랜치와 GSI 호환 패치 출처·라이선스 확인

후보 GSI의 VINTF 대조에는 [실기에서 읽은 vendor 선언](../tests/fixtures/plf02wh/vendor/etc/vintf)을 사용한다. 대상 framework 쪽 매트릭스와 manifest가 준비되면 양방향 호환성, VNDK 30 라이브러리, 커널 요구 사항을 확인한다. 11월 17일 백업에서 확인한 파티션 예산과 현재 실기 마운트 구성은 [기기 상태](device-status.md)에 기록했다.

## 2. 빌드 재현 환경 설계
- [ ] 호스트 아키텍처, 지원 Linux 버전, RAM/디스크/네트워크 요건 확인
- [ ] 소스 revision 및 도구 버전을 고정한 manifest 계획
- [ ] 기존 kernel/vendor/odm 유지한 소스 기반 GSI 접근 가능성 판정
- [ ] 사용자 앱 제외로 얻는 용량을 실제 이미지 기준 측정
- [ ] GApps와 보안 목표를 포함한 최종 공간 예산 작성

현재 빈 manifests/configs는 빌드 가능한 구성으로 오해하지 않도록 샘플 명령을 넣지 않았습니다. 최신 AOSP를 단순 축소하면 부팅된다고 가정하지 않습니다.
