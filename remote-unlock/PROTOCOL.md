# 공통 승인 프로토콜 v1

## 목적과 범위

PLF02WH와 Mac은 외부 상시 서버에 각각 연결한다. 서버는 승인 메시지를 중계한다. 이 프로토콜의 승인 성공은 OS 잠금 해제 성공과 다르다. v1의 승인 수단은 명시적 수동 승인이고 얼굴 인식 결과를 주장하지 않는다.

운영 연결은 WSS다. 로컬 자동 시험에만 loopback WS를 사용한다. 서버는 각 장치의 공개키와 허용된 요청자·승인자·계정 조합을 보유한다. 최초 등록은 운영자가 검토한 설정 파일로 수행한다. 공개키 등록을 인터넷의 익명 등록 요청에 맡기지 않는다. 개인키·PC 비밀번호·얼굴 영상은 서버에 전달하지 않는다.

## 서명과 메시지

서명은 표준 JWS Compact Serialization, ES256, P-256을 사용한다. protected header는 `alg=ES256`, `typ=remote-unlock+jws`, `kid=issuer`이며 그 외 헤더는 받지 않는다. 서명된 원문을 그대로 전달하고 JSON을 재직렬화해서 서명을 재구성하지 않는다. 모든 객체는 아래 필드만 허용한다.

공통 필드는 `version=1`, `kind`, `issuer`, `audience`, `issuedAt`, `expiresAt`다. 시각은 Unix 초 단위 정수이며 유효 기간은 최대 60초다. 발행 시각의 미래 편차는 최대 5초, 만료 시각 이후는 거부한다. ID는 영문·숫자·밑줄·하이픈 1–64자로 제한한다.

| kind         | 추가 필드                                | 의미                                                                      |
| ------------ | ---------------------------------------- | ------------------------------------------------------------------------- |
| authenticate | nonce                                    | 해당 소켓에서 서버가 발급한 32바이트 난수에 서명                          |
| request      | requestId, nonce, account, action        | UUID 요청 ID, 32바이트 난수, 대상 Mac의 로컬 계정 식별자, `screen-unlock` |
| decision     | requestId, requestHash, decision, method | 원본 요청 JWS의 SHA-256, `approve` 또는 `deny`, `manual`                  |

nonce와 requestHash는 패딩 없는 canonical base64url로 표현한다. `requestHash`는 원본 요청 JWS 문자열의 UTF-8 바이트를 해시한다. 계정은 비밀번호가 아닌 로컬 매핑용 식별자다.

## 연결과 요청 수명

서버는 연결마다 일회용 인증 nonce를 발급한다. 클라이언트는 서버 ID를 audience로 한 authenticate 메시지에 서명한다. 등록 공개키로 인증하기 전에는 중계할 수 없다. 다른 연결의 인증 메시지 재사용은 거부한다.

요청자는 허용된 승인자에게 요청을 보낸다. 승인자는 등록된 요청자 공개키로 원본을 검증하고 대상·계정·만료를 확인한 뒤 승인 또는 거부에 서명한다. 요청자는 승인자 공개키로 응답을 검증하고 요청 ID·원문 해시·대상·유효 기간이 대기 중인 요청과 일치할 때 한 번만 소비한다. 응답의 만료는 요청 만료보다 늦을 수 없다.

연결 종료·요청 취소·프로세스 재시작은 대기 요청을 무효화한다. 오프라인 승인을 저장했다가 나중에 실행하지 않는다. 중복·오래된 요청이나 응답은 새 잠금 해제에 사용하지 않는다.

## 검증 기준

정상 승인과 거부, 잘못된 키·대상·계정, 위조·변조, 만료, 중복 응답, 연결 종료 후 응답을 검증한다. 서버를 통한 실제 메시지 왕복도 시험한다. Mac의 실제 OS 잠금 해제는 별도 연동 증거가 필요하다.
